\section{Task 3: Manipulation}
\label{sec: Task 3}

\begin{frame}{Task 3: Pick \& Place}

    \begin{block}{Objective}
        Execute a precise \textbf{Pick \& Place} operation leveraging on:
        \begin{itemize}
            \item The \textbf{map} generated in Task 1
            \item The \textbf{marker locations} identified in Task 2
        \end{itemize}
    \end{block}

    \vspace{0.1cm}

    \textbf{Operational Constraints}
    \par
    The manipulation task requires strict \textbf{mechanical} and \textbf{spatial tolerances}:
    \vspace{0.2cm}
    \begin{itemize}
        \item \textbf{Grasp Tolerance:} The parallel gripper has \textbf{minimal mechanical compliance}. Even slight ArUco pose estimation errors (\textit{homography noise}) can cause the fingers to collide with the object rather than grasping it
    
        \item \textbf{Kinematic Reachability:} Placement success is \textbf{strictly coupled} with \textbf{Base Positioning}. If the robot stops too far from the table, the arm's maximum reach is insufficient
        
        \item \textbf{Deployment Safety:} Transitioning the arm from the \textit{Safe Travel Configuration} to the \textit{Work Configuration} near obstacles poses a \textbf{high risk} of \textbf{collision} with the table edge
    \end{itemize}

\end{frame}

\begin{frame}{Task 3: Coordinator}

    The \texttt{coordinator\_task3} node orchestrates the sequence, bridging the data gathered in Task 1 and Task 2 with the actuation logic.

    \vspace{0.1cm}

    \begin{block}{Execution Workflow}
        \begin{enumerate}
            \item \textbf{Data Ingestion:} Parses \texttt{marker\_locations.csv} to retrieve the exact pose of the tables targets found during Task 2 exploration
            \item \textbf{State Sequence:} Enforces the required order of operations:
            {
                \small
                $$ \text{Localize} \xrightarrow{\text{Navigate to Pick}} \text{Pick Cube ID 63} \xrightarrow{\text{Navigate to Place}} \text{Place Cube ID 63} $$
                $$ \text{Next Target} \xrightarrow{\text{Navigate to Pick}} \text{Pick Cube ID 582} \xrightarrow{\text{Navigate to Place}} \text{Place Cube ID 582} $$
            }
            \item \textbf{Visual Feedback:} Publishes dynamic TF frames (\texttt{target\_cube\_frame}) to visualize the manipulation target in RViz in real-time
        \end{enumerate}
    \end{block}

    \vspace{0.2cm}

    Once all targets cubes are processed, the coordinator commands the robot to return to the \textbf{Home Position}, signaling Task 3 completion.

\end{frame}

\begin{frame}{Task 3: Manipulator}

    The \texttt{manipulator} node orchestrates the sequence, handling the actual arm movements and gripper actions on the basis of the \texttt{coordinator\_task3} commands.
    The commands are in the form of:
    \begin{itemize}
        \item \textbf{Pick Command:} \texttt{'PICK\_<cube\_id>'}
        \item \textbf{Place Command:} \texttt{'PLACE\_<cube\_id>'}
    \end{itemize}   

    This commands issue the manipulator node to execute the corresponding manipulation sequence:
    \begin{block}{\texttt{PICK\_<63>}}
        {
            \small
            $$ \text{Safe Pose} \xrightarrow{\text{Idle for aruco pose update}} \text{Pre\_Grasp} \rightarrow \text{Grasp} \rightarrow \text{Post\_Grasp} \rightarrow \text{Safe Pose} $$
        }
    \end{block}

    \vspace{0.1cm}
    
    \begin{block}{\texttt{PLACE\_<63>}}
        {
            \small
            $$ \text{Safe Pose} \xrightarrow{\text{Idle for place station}} \text{Pre\_Release} \rightarrow \text{Release} \rightarrow \text{Post\_Release} \rightarrow \text{Safe Pose} $$
        }
    \end{block}

    \vspace{0.1cm}

\end{frame}

\begin{frame}{Task 3: Grasp \& Release Selection Pose}
    \begin{block}{Pose Calculation}
        The Grasp Pose is computed by extracting the marker's transform. The choice of the grasping point has been made to ensure a stable grip on the cube, considering collinear and antipodal grasp for the 7cm cube.
    \end{block}

    \begin{columns}[c]
        \begin{column}{0.6\textwidth}
            \begin{exampleblock}{Pose Computation (KDL)}
                \small
                Given the marker pose $^{base}T_{marker}$, we compute the approach vector by applying a geometrical offset:
                \[
                    ^{base}T_{appr} = ^{base}T_{marker} \cdot \underbrace{T_{rotY(90^\circ)}}_{\text{Rotation}} \cdot \underbrace{T_{appr}}_{\text{Translation}}
                \]
                This aligns the gripper normal with the cube's face.
            \end{exampleblock}
        \end{column}

        \begin{column}{0.4\textwidth}
            \begin{figure}
                \centering
                \includegraphics[width=0.8\linewidth, height=3cm, keepaspectratio]{Planning5.png}
                \caption{TF Frames visualization}
            \end{figure}
        \end{column}
    \end{columns}

    \vspace{0.3cm}
    \textbf{Placement Logic:}
    The release pose is derived from the grasp pose but lifted vertically to ensure the object rests on the table:
    $$ P_{release_{z}} = P_{grasp_{z}} + 0.15m $$

\end{frame}

\begin{frame}{Task 3: Manipulation Safety \& Robustness}

    \begin{center}
        The manipulation sequence follows a strict cycle:
        $$ \text{Pre\_op} \rightarrow \text{op} \rightarrow \text{Post\_op} \rightarrow \text{Safe Pose} $$
    \end{center}
    
    \begin{alertblock}{Motion Safety: Decoupled Retraction}
        The $0.4m$ approach offset requires the \texttt{arm\_torso} group to extend significantly. To prevent the torso from lowering while the arm is still over the table (risk of collision), we implemented a **Decoupled Safe Procedure**:
        \begin{enumerate}
            \item \textbf{Arm First:} The arm retracts to a folded configuration while the torso remains fixed
            \item \textbf{Torso Second:} Only once the arm is safe, the torso lowers to the travel height
        \end{enumerate}
    \end{alertblock}
    \textbf{Environmental Awareness:}
    Upon arrival, \textbf{Collision Objects} representing the table (known dimensions) are spawned in MoveIt to forbid planning through the surface.
\end{frame}

\begin{frame}{Task 3: Precision Placement Strategy}

    To ensure accurate object placement, we adopted a \textbf{Relative Pose Replication} strategy rather than absolute coordinate planning.
    
    \vspace{0.3cm}

    \begin{columns}
        \begin{column}{0.6\textwidth}
            \textbf{The Logic:}
            \begin{itemize}
                \item The robot records the exact \textbf{base-to-table distance} ($d_{ref}$) during the successful Grasp phase
                \item This distance is enforced as a constraint during the Placement phase to guarantee the \textbf{arm's kinematic reachability}
            \end{itemize}
        \end{column}

        \begin{column}{0.4\textwidth}
            \begin{alertblock}{Why?}
                Reusing the grasp pose relative to the base minimizes Inverse Kinematics (IK) errors and ensures the object lands exactly on the table surface.
            \end{alertblock}
        \end{column}
    \end{columns}

    \vspace{0.1cm}

    \begin{block}{Active Error Correction (Closed-Loop)}
        Since AMCL localization has a margin of error ($>2cm$), the robot performs a final \textbf{Linear Approach/Backup} maneuver before placing: $$e = d_{real} - d_{ref}$$
        
        If $|e| > 1.0\text{cm}$: The base adjusts its position ($v_x = \pm 0.1 \text{m/s}$) until convergence.
    \end{block}

\end{frame}

\begin{frame}{Task 3: Grasping Dynamics}

    Mobile manipulation in physics engines (Gazebo/ODE) suffers from unreliable \textbf{contact dynamics} and friction simulation, often leading to object slippage during base motion.

    \vspace{0.05em}

    \begin{columns}[c] % [t] aligns columns at the top
        \begin{column}{0.5\textwidth}
            \begin{block}{Attempt 1: Force Control (Failed)}
                We initially attempted a realistic grasp based on Force/Torque sensor feedback:
                \begin{itemize}
                    \item \textbf{Tuning:} Adjusted friction coefficients ($\mu$) and contact compliance ($k_p, k_d$)
                    \item \textbf{Logic:} Stop gripper closure upon reaching a force threshold ($F_{th} = 10\text{N}$)
                \end{itemize}
                \textit{Outcome: Proven unreliable due to physics engine instability}
            \end{block}
        \end{column}

        \begin{column}{0.4\textwidth}
            \begin{exampleblock}{Solution: Kinematic Locking}
                To guarantee transport stability, we bypassed the physics engine using the \textbf{Link Attacher Plugin}.
                \begin{itemize}
                    \item \textbf{Mechanism:} Creates a rigid kinematic joint (Fixed Joint) between the gripper and the object
                    \item \textbf{Result:} Zero slippage and robust transport regardless of base accelerations
                \end{itemize}
            \end{exampleblock}
        \end{column}
    \end{columns}

\end{frame}
